# Cashfire 2 shooting spree

`dist/bonus.js` preserves the original global `LiveWireBonus` contract: `profile`, `pick`, `open`, `draw`, `bind`, and `active`. It also exposes the same object as `window.LiveWireBonus` for isolated review. The game wallet remains in Live Wire's existing settlement path; this module never debits, refunds or credits money. A guarded `onCollect(acceptedMultiplier)` runs once when Return to reels is pressed.

Normal prizes remain 10, 15, 20, 30, 50 and 100× at weights 60, 10, 10, 10, 5 and 5. Their mean is 20×. Mega prizes remain 30, 50, 100, 250, 500 and 1,000× at weights 50, 20, 10, 10, 4 and 6. Their mean is 140×. A mean is not an individual prize. WebCrypto rejection sampling and integer 0–99 tickets preserve the original draw.

The accepted total is clearly locked independently of the film's kill counter. The five existing films cannot represent all Live Wire prize values through the old Cashfire kill paytable, so that ladder is not used. Kills are explicitly labelled footage kills and never recalculate the bonus. The user sees the exact total stake return and can skip the film without losing any accepted award. No certified RTP claim is made by this module.

Each feature plays one finite original native clip. Normal presentation rotates sprint, four-kill extraction, early ambush, late ambush and maximum extraction. Mega rotates maximum extraction, late ambush, four-kill extraction, sprint and early ambush. Selection is deterministic presentation state and consumes no outcome random number. Each mode has its own title, colour and original reward ceiling. No loops, new edits, cuts, cutout enemies or additional montages are introduced. The supplied maximum clip already contains an editorial insert, as disclosed by its original README.

`combat-media.js` is the existing tested loader with only its catalog import path adapted. `combat-media-catalog.js` and native transport assets are unchanged. Four films reconstruct from 43 parts, each at most 4 MiB; the 17,444,048-byte early ambush remains direct. Full native data totals 188,700,504 bytes. SHA-256 verification requires HTTPS or localhost. The loader checks each part and the completed file before creating a native video Blob. The direct small film retains browser progressive playback; its exact source hash is checked by tests.

The native media clock controls film kills and endpoints: sprint30s, early ambush9.9s, late ambush21.8s, four-kill30s, maximum30s. Native AAC remains the combat audio, synchronized to the reel sound control. Films are 1280×720 H.264 at24fps. The UI contains the full frame rather than cropping the action.

Loading shows byte progress and holds the native clock. Failed, corrupt, incomplete or timed-out media offers retry of the same film or continue to the accepted award. Skip aborts pending work and discards late results; old object URLs are revoked. A retry cannot reroll film or money. Video pause, hidden tabs and autoplay gesture rejection hold the same accepted result, with manual resume. A hidden tab encountered during loading also holds the completed load until resume. Sixty-second loading timeout is recoverable through the same fallback. The module uses native playback, timeupdate and the host draw callback; it adds no independent animation loop.

The canonical `bonus-markup.html` dialog is shared by the main game and isolated review. Preview-only fixtures accept `open({count,stake,multiplier,onCollect,preview:true,fixture:{clipIndex,paused,mediaFailure}})`. `clipIndex`0–4 selects sprint, early ambush, late ambush, four-kill extraction or maximum extraction. Fixtures are rejected when preview is false and do not change the prize support. Pause/resume can be driven through the real `bonusPause`/`bonusResume` buttons. Continue and Return to reels use the same production handlers.

Verified locally: 13 state-machine tests pass, covering exact supports/weights/means, fixed awards, collect once, skip and late result cleanup, failure/retry/continue, manual pause, backgrounding during playback/loading, gesture rejection, mute sync, invalid media duration, five finite films and timeout. Three additional tests verify all native hashes, a real shipping-parts-to-Blob load and upload-size limits. These are Node tests with a simulated DOM/native video at the module boundary; actual visual playback, audible synchronization and physical mobile performance require browser/device review. All five original video/audio streams separately decoded successfully with FFmpeg during the asset audit.
